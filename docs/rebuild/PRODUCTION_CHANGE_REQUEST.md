## 2. ขอบเขตของการเปลี่ยนแปลงรอบแรก

**deploy โค้ดโดยไม่เปิด flag ใด ๆ** ผลที่คาด: ระบบทำงานเหมือนเดิม ยกเว้นสิ่งที่เปิดเสมอและทดสอบแล้ว
1. หัว no-store / no-referrer / noindex ของหน้าส่วนตัว
2. ตรวจลูกค้าขอไม่รับการติดต่อตอนส่ง (`contact_block`)
3. ยกเลิกงานติดตามผลที่ค้างเมื่อลูกค้าตอบกลับ
4. ตาราง/คอลัมน์ใหม่แบบเพิ่มอย่างเดียว

การเปิด flag ทำเป็นคำขอแยกทีละกลุ่มตาม OPERATIONS_RUNBOOK §2

## 3. ขั้นตอน (ผู้ดูแลเซิร์ฟเวอร์ · กรอก `<…>` จากเครื่องจริงก่อน)

```bash
# 3.1 ระบายงาน: กด "หยุดคิวทั้งหมด" ที่ /admin/jobs และ "หยุดเอเจนต์ทั้งหมด" ที่ /admin/tasks (ถ้ามีหน้านั้น)

# 3.2 สำรอง (SQLite)
sqlite3 <path-to-db> ".backup '<backup-dir>/geo-$(date +%Y%m%d-%H%M).db'"
# หรือ Postgres
pg_dump -Fc -f <backup-dir>/geo-$(date +%Y%m%d-%H%M).dump <database-url-from-env>

# 3.3 ตรวจไฟล์สำรอง (นับแถวตารางหลัก)
sqlite3 <backup-file> "SELECT 'leads',COUNT(*) FROM leads UNION ALL SELECT 'quotes',COUNT(*) FROM quotes UNION ALL SELECT 'acct_docs',COUNT(*) FROM acct_docs UNION ALL SELECT 'tenants',COUNT(*) FROM tenants;"

# 3.4 ดึงโค้ด (commit ที่ผ่าน staging เท่านั้น)
cd <app-dir> && git fetch && git checkout <commit-ที่ผ่าน-staging>

# 3.5 รีสตาร์ต service (init_db เพิ่มตาราง/คอลัมน์ตอนเริ่ม)
sudo systemctl restart <service-name>

# 3.6 ตรวจหลัง deploy
sqlite3 <path-to-db> "PRAGMA integrity_check;"
sqlite3 <path-to-db> "SELECT version FROM schema_migrations ORDER BY version;"
# เทียบจำนวนแถวกับ 3.3
```

## 4. ตรวจหลัง deploy (ไม่ส่งอะไรถึงลูกค้า)

- [ ] `/` และ `/login` เปิดได้ · admin ล็อกอินได้ · ลูกค้าทดสอบของทีมล็อกอินได้
- [ ] `/admin`, `/admin/leads/<id ทดสอบ>`, `/app` (บัญชีทดสอบ) เปิดได้
- [ ] header ของ `/admin` มี `Cache-Control: private, no-store` (ตรวจผ่าน proxy จริง)
- [ ] webhook ลายเซ็นผิดถูกปฏิเสธ (ยิงด้วยลายเซ็นปลอมจาก curl: LINE ต้องได้ 403 และ Stripe ต้องได้ 400) — ไม่ต้องยิงของจริง
- [ ] log ไม่มี error ใหม่ภายใน 30 นาที
- [ ] เปิดคิวกลับ

## 5. ผลกระทบที่คาด

- ช่วงหยุดคิว งานตามเวลาจะเลื่อนออกไป (ทำต่อเมื่อเปิดกลับ)
- หัว no-store อาจทำให้หน้าหลังบ้านโหลดช้าลงเล็กน้อยเพราะไม่ใช้แคช
- **ยังไม่ได้วัด** ระยะเวลา downtime และเวลาย้ายบนข้อมูลขนาดจริง (ซ้อมแค่ข้อมูลสมมติ 2,000 ลีด ซึ่งใช้ 0.1 วินาที) ต้องวัดบน staging ก่อน
