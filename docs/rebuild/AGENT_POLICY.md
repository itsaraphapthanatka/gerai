# นโยบายเอเจนต์ AI (stage 14)

flag: `agent_policy` (ปิดเป็นค่าเริ่มต้น · ปิด = พฤติกรรมเดิมทุกอย่าง) · โค้ด: `app/agent_policy.py` · เทสต์: `agent_policy_smoke.py`

ต่อยอดของเดิม (`orchestrator` แจกงาน, `ceo_chat` สั่งงาน, `execs` กรอบอำนาจ, `skills` ทักษะ, `jobs` การอนุมัติ/งบ)
ไม่มี framework หรือ subscription ใหม่

## 1. ระดับอำนาจ (บังคับในโค้ด ไม่ใช่ใน prompt)

| ระดับ | ความหมาย | เอเจนต์/โมเดลสั่งเอง | เจ้าของสั่งในแชต |
|---|---|---|---|
| A | ร่าง/อ่านภายใน ย้อนได้ | ทำได้ | ทำได้ |
| B | ใช้เงิน/ทรัพยากรในเพดาน | ทำได้ถ้างบเหลือ | ทำได้ (มีค่าใช้จ่าย = พิมพ์ยืนยัน) |
| C | ติดต่อคนนอก / เผยแพร่ | อนุมัติตรงงาน หรือกฎประจำที่เจ้าของเปิด (ปิดเป็นค่าเริ่มต้น) | พิมพ์ยืนยัน |
| D | การค้า / สิทธิ์ (ราคา ส่วนลด คืนโหมดอัตโนมัติ) | อนุมัติตรงงานเท่านั้น ไม่มีกฎประจำ | พิมพ์ยืนยัน |

- ระดับมาจากตาราง `TOOLS` เท่านั้น คีย์ที่โมเดลใส่มาเพื่อยกระดับ (`level`, `approved`, `approval_id`, `force`, `override` …) ถูกทิ้งและบันทึกไว้
- คะแนนความมั่นใจอย่างเดียวไม่อนุญาตอะไร โหมด "ตัดสินเอง" เดิมต้องผ่านด่านสถิติ **และ** เจ้าของกดเปิดเอง ซึ่งนับเป็นกฎประจำ
- `pause` ทำได้เสมอ เพราะเป็นการลดอำนาจ ส่วน `resume` (คืนอำนาจ) เป็นระดับ D

## 2. งานแต่ละอย่าง (สัญญา)

แต่ละงานใน `TOOLS` ระบุข้อมูลเหล่านี้:
- กลุ่ม (ค้นคว้า / หลักฐาน / หาลูกค้า / ส่งมอบ / ควบคุมระบบ)
- ขอบเขตบัญชี (lead / leads / global)
- อินพุตแบบมีชนิด (str ความยาวสูงสุด / int ช่วง / enum / num) โดยคีย์นอกสคีมาถูกทิ้ง
- ผลที่ได้ หลักฐานที่ต้องมี ค่าใช้จ่ายโดยประมาณและงบที่ใช้ ช่องทางภายนอกที่กระทบ
- เกณฑ์สำเร็จ / ส่งต่อคน / ยกเลิก
- เพดานครั้งต่อวัน

## 3. ลำดับการตัดสิน `authorize()`

1. ไม่มีงานนี้ในรายการ → ไม่อนุญาต
2. อินพุตผิดชนิดหรือนอกช่วง → ไม่อนุญาต
3. หยุดฉุกเฉิน (`agents_paused` หรือคิว `agent:<tool>`) → พักไว้ ยกเว้นระดับ A
4. ข้ามบัญชี (งานผูกลีด X แต่อ้างลีดอื่นผ่าน `lead_id` หรือ `domain`) → ไม่อนุญาต
5. งาน C/D กับลูกค้าที่ขอไม่รับการติดต่อ → ไม่อนุญาต
6. งานเดิมข้อมูลเดิมได้รับอนุญาตครบ 3 ครั้งใน 60 นาที → ถือว่าวนซ้ำ ไม่อนุญาต
7. ครบเพดานครั้งต่อวัน → ไม่อนุญาต
8. งบวันนี้ไม่พอ (`jobs.budget_used` + ค่าประมาณ เกิน `budget_limit`) → ไม่อนุญาต
9. ตรวจอำนาจตามระดับ (ข้อ 1)

ทุกการตัดสินถูกบันทึกในตาราง `agent_actions`:
- ที่มา ผู้สั่ง ระดับ และผลการตัดสินพร้อมเหตุผล
- ข้อมูลที่ปิดข้อมูลส่วนตัวแล้ว (อีเมล เบอร์ คีย์ และ query string)
- hash ของงาน การอนุมัติ ค่าใช้จ่าย และผลลัพธ์

## 4. การอนุมัติ

- **งานที่ CEO แจก (C/D):** สถานะเป็น "รออนุมัติ" แล้วเจ้าของกด "อนุมัติงานนี้ครั้งเดียว" ที่ `/admin/tasks`
    - ระบบสร้างการอนุมัติด้วย `jobs.grant` โดยผูกกับชื่องาน ข้อมูลของงาน และ id งาน ใช้ได้ครั้งเดียวภายใน 24 ชั่วโมง
    - ถ้าข้อมูลของงานถูกแก้หลังอนุมัติ ระบบตอบ `mismatch` ถ้าเอาการอนุมัติไปใช้กับงานอื่น ระบบตอบ `already_used` ทั้งสองกรณีไม่อนุญาต
- **แชต CEO:** การยืนยันผูกกับ hash ของงาน ข้อมูล และข้อความที่เจ้าของเห็น
    - ถ้าราคา ช่องทาง หรือสถานะเปลี่ยนระหว่างรอยืนยัน ระบบจะไม่ทำ แสดงรายละเอียดใหม่ และถามยืนยันอีกครั้ง
- **กฎประจำ** (`agent_rule_<tool>`) ตั้งได้เฉพาะงานระดับ C และปิดเป็นค่าเริ่มต้น งานระดับ D ตั้งไม่ได้

## 5. ข้อมูลภายนอกไม่น่าไว้ใจ

- อีเมลลูกค้า (คัดประเภท ร่างคำตอบ) และคำถามที่ส่งเข้าตัวตอบแชตขาย ถูกห่อด้วย `fence()` ก่อนใส่ prompt
    - ข้อความถูกตัดไม่เกิน 1,500 ตัวอักษร และตัวคั่นปลอมถูกลบ
    - prompt บอกโมเดลชัด ๆ ว่าห้ามทำตามคำสั่งในบล็อกนี้
- อีเมลที่มีข้อความพยายามสั่ง AI (`injection_signals`)
    - คำตอบไม่ถูกส่งอัตโนมัติ แม้เปิดโหมดตอบเองไว้ ต้องรอคนดู
    - ระบบตั้งธงเตือนใน `agent_actions`

## 6. ลำดับความสำคัญ / กำลัง / ลองใหม่

- ลำดับความสำคัญตั้งที่ setting `agent_priority` (JSON) ค่าเริ่มต้น: โทร > ติดตามผล > ถาม AI > หาช่องทาง > หาลูกค้า > การตลาด
- กำลังต่อวันตั้งที่ `agent_capacity_daily` (ค่าเริ่มต้น 8) งานที่เกินกำลังถูกพักไว้พร้อมเหตุผล ไม่ทิ้งเงียบ
- งานที่ล้ม ข้าม พักไว้ หรือไม่อนุญาต สั่งใหม่ได้รวมไม่เกิน 3 ครั้ง
- ผลที่ไม่ได้ทำจริง (เช่น ยังไม่ได้ตั้งค่า Serper) แสดงเป็น "ข้าม" ไม่ใช่ "เสร็จ"
- เอเจนต์ไม่แก้กลยุทธ์ ราคา นโยบายกฎหมาย หรือสิทธิ์ เพราะไม่มีงานแบบนั้นในรายการ

## 7. ทักษะ (skills)

เมื่อเปิด flag ทุก system prompt ของงานโมเดลจะต่อท้ายด้วย `CAPABILITY_NOTE` ซึ่งเจ้าของแก้ทับไม่ได้ เนื้อหาคือ:
- สิ่งที่ระบบทำได้จริง
- ความหมายของตัวเลขแต่ละประเภท
- "ยังไม่ได้ทดสอบ ≠ 0"
- ห้ามรับประกันผล
- ทำไม่ได้ให้บอกตรง ๆ

## 8. หน้าปฏิบัติการ `/admin/tasks` (เมื่อเปิด flag)

- ตารางงาน: ระดับอำนาจ สถานะใหม่ (รออนุมัติ / ไม่อนุญาต / ข้าม) ปุ่มอนุมัติ และปุ่มสั่งใหม่พร้อมจำนวนครั้งที่ลองแล้ว
- กติกา ลำดับความสำคัญ และกำลังต่อวัน
- กฎประจำ: เปิด/ปิดได้ทีละงาน
- บันทึกการตัดสินของนโยบาย (ปิดข้อมูลส่วนตัวแล้ว)
- ปุ่มหยุดเอเจนต์ทั้งหมด (kill switch)

## ยังไม่ครอบคลุม

- งานที่วิ่งผ่าน `pipeline` / `decisions` โดยตรง (ทักลีดใหม่ ติดตามผลรายลีด โพสต์) ยังใช้ระบบอนุมัติเดิมของ `decisions` ซึ่งเป็นกฎประจำที่เจ้าของเปิดเอง นโยบายนี้คุมเฉพาะชั้นที่ CEO แจกงานและแชต CEO
- ยังไม่ได้ทดสอบกับโมเดลจริง (เทสต์ใช้ตัวตอบปลอม)
- ยังไม่ได้ทดสอบ Postgres
