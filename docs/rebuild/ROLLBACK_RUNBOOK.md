# คู่มือถอยกลับ (Rollback Runbook) — stage 18

## ระดับการถอย (เลือกระดับเล็กที่สุดที่แก้ปัญหาได้)

| ระดับ | ทำอะไร | ข้อมูล | ใช้เมื่อ |
|---|---|---|---|
| 1. หยุดชั่วคราว | kill switch ที่ `/admin/jobs` · หยุดเอเจนต์ที่ `/admin/tasks` · หยุดเฉพาะประเภทงาน/ช่องทาง/ลีด | ไม่เปลี่ยน | สงสัยว่าส่งผิด/ซ้ำ ต้องการเวลาดู |
| 2. ปิด flag | setting `flag_<ชื่อ>` = "0" | ไม่หาย (เทสต์ `release_regression_smoke.py` ยืนยัน) | ฟีเจอร์ใหม่ทำงานผิด |
| 3. ถอยโค้ด | deploy commit ก่อนหน้า | DB ที่ย้ายแล้วใช้กับโค้ดเก่าได้ (ซ้อมแล้ว) | โค้ดพังทั้งระบบ |
| 4. กู้ DB | ไฟล์สำรองตาม MIGRATION_RUNBOOK ข้อ 5 | ข้อมูลหลังสำรองหาย | ข้อมูลเสีย |

## ถอยแล้วต้องไม่ปลุกของเก่าขึ้นมาส่ง

ทุกตัวต่อไปนี้มีเทสต์ยืนยัน:
- **ข้อความนัดในคิว**
    - ตรวจเวอร์ชันนัดและสถานะตอนจะส่ง ถ้านัดถูกเลื่อน/ยกเลิก หรือลูกค้าขอหยุดระหว่างนั้น งานจะยกเลิกตัวเอง
    - เทสต์: `appointments_smoke.py`
- **การเผยแพร่**
    - การอนุมัติผูกกับ hash ของเนื้อหา ถ้าเนื้อหาถูกแก้ระหว่างที่ปิด flag (ทางเดิม) เมื่อเปิดกลับ คำขอเดิมส่งไม่ได้ ต้องตรวจและอนุมัติใหม่
    - เทสต์: `release_regression_smoke.py`, `publishing_smoke.py`
- **งานของเอเจนต์**
    - การอนุมัติใช้ได้ครั้งเดียวและผูกข้อมูลงาน หยุดฉุกเฉินจะถูกตรวจซ้ำตอนลงมือ
    - เทสต์: `agent_policy_smoke.py`
- **การทดสอบ AI แบบเสียเงิน**
    - ปิดสวิตช์หลังงานเข้าคิวแล้ว งานจะยกเลิกก่อนเรียก AI
    - เทสต์: `ai_tests_smoke.py`
- **ลูกค้าขอไม่รับการติดต่อ**
    - ระบบตรวจตอนส่งทุกครั้ง (`contact_block`) ไม่ใช่ตอนสร้างงาน
    - เทสต์: `sales_smoke.py`, `release_regression_smoke.py`

## สิ่งที่ปิด flag แล้ว "ไม่ย้อนกลับเอง"

ต้องตัดสินใจเอง:
- **อีเมลหรือข้อความที่ส่งไปแล้ว:** เรียกคืนไม่ได้
- **ชิ้นที่เผยแพร่ไปแล้ว:** ยังอยู่บนเว็บลูกค้า ถ้าจะเอาลง ให้ใช้ "คืนเวอร์ชัน" ก่อนปิด flag หรือแก้ที่ปลายทางเอง
- **การปิด `publish_v2`:** auto-publish แบบเดิมจะกลับมาทำงานกับแบรนด์ที่ตั้งไว้ ถ้าไม่ต้องการ ให้ปิด auto-publish รายแบรนด์ก่อน
- **การปิด `delivery_v2`:** Autopilot เดิมจะกลับมาวิ่งกับแบรนด์ที่เปิดไว้ รวมแบรนด์ที่พื้นที่งานยังรอข้อมูลด้วย ถ้าไม่ต้องการ ให้ปิด Autopilot รายแบรนด์ก่อน
- **การปิด `scheduler_lease`:** ถ้ามีหลายโปรเซสตั้ง GEO_AUTORUN=1 ทุกโปรเซสจะวิ่งรอบเดียวกันอีก ให้ลดเหลือโปรเซสเดียวก่อน

## เช็กหลังถอย

1. `/admin` และ `/app` เปิดได้ และลูกค้าเดิมล็อกอินได้
2. นับแถวตารางหลักตรงกับก่อนถอย
3. `/admin/jobs` ไม่มีงานที่กำลังส่งค้าง
4. เปิด kill switch กลับเมื่อพร้อม
