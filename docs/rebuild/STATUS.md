## stage 06A-1 — คุยต่อใน LINE จากรายงาน
**เส้นทาง:** ปุ่ม "คุยต่อใน LINE" ในส่วนขอแผนของรายงาน → `GET /audit/{token}/line` ออกรหัส 6 ตัวใช้ครั้งเดียว (อายุ 72 ชม. · กดซ้ำได้รหัสเดิม) → พาไป `https://line.me/R/oaMessage/@<OA>/?ขอแผนจากรายงาน <โดเมน> · รหัส XXXXXX` → ลูกค้ากดส่งเอง → webhook จับรหัส
- ผูกบัญชี LINE กับลีด (เฉพาะลีดที่ยังไม่มี LINE · มีของคนอื่นแล้ว = ไม่เขียนทับ คุยต่อได้ด้วยสถานะแชต) · สร้างแถว `plan_requests` (channel `line`, source `line_oa`) ผ่าน `plan_request.submit` ตัวเดิม → `wants_call` + แจ้งทีม + Sales Brief เดียวกับฟอร์ม · ถ้ามีคำขอจากฟอร์มแล้ว = ผูกกับคำขอเดิม ไม่สร้างซ้ำ
- บอทตอบ 3 ข้อความ: เรื่องที่ควรแก้ก่อน (จาก `report_view`) + ลิงก์รายงาน · แจ้งการใช้ข้อมูลและวิธีถอน ("หยุดติดต่อ") · ข้อ 1 อยากเริ่มเมื่อไร → ข้อ 2 ใครดูแลเว็บ → รับข่าวสารไหม (ค่าเริ่มต้นไม่รับ · เปลี่ยนใจ = เพิ่มบันทึกใหม่ เก็บของเดิม) → "ทีมจะทักกลับในแชตนี้ภายใน 1 วันทำการ" + [ขอให้โทรหาแทน]
- ขอเบอร์ในแชตเฉพาะคนที่กดขอให้โทร · เบอร์เข้า Sales Brief และ `leads.contact` · ข้อความแจ้งทีมไม่มีเบอร์หรือ LINE userId · พิมพ์เรื่องอื่นระหว่างรอเบอร์ = เลิกรอ ให้บอทเดิมตอบ
- "หยุดติดต่อ" = คำขอเป็น `withdrawn` + ถอนรับข่าวสาร + แจ้งทีม · Brief ขึ้น "ห้ามติดต่อ"
- กันเดารหัส: ผิด 5 ครั้งใน 1 ชม. = ไม่รับรหัสจาก LINE นั้นชั่วคราว · ไม่ส่ง token รายงานเข้าไปในข้อความที่ OA เห็น · ปุ่มตอบเร็วรับเฉพาะคนที่มีสถานะแชตและค่าที่อยู่ในรายการ
- **พักบอท:** หน้า `/admin/leads/{id}#brief` มีปุ่ม "พักบอท 24 ชม." / "เปิดบอทกลับ" (CSRF) · ระหว่างพัก บอทไม่ตอบห้องนั้นเลย (บันทึกในไทม์ไลน์ว่ามีข้อความเข้า) → ทีมตอบเองใน LINE OA Manager
- ตารางใหม่ (เพิ่มอย่างเดียว): `line_plan_codes`, `line_plan_sessions` · `app/line_plan.py` (ใหม่) · `line_oa`: `oa_id()`, `reply_messages()`, อ่าน postback · **LINE ID ของ OA อ่านจาก OA ที่เชื่อมอยู่** (`GET /v2/bot/info` → `basicId` · อ่านอย่างเดียว · เก็บไว้ใน settings `line_oa_id_auto` · ถามไม่ได้ = เว้น 1 ชม. ก่อนถามใหม่ · เปลี่ยน token = ลืมค่าเดิม) · ใส่เองทับได้ที่หน้าตั้งค่า LINE หรือ env `GEO_LINE_OA_ID`
- ปุ่มขึ้นเมื่อ: `plan_request_v2` + `line_appointments` active **และ** มีคีย์ Messaging API **และ** ใส่ LINE ID ของ OA แล้ว · ปิด flag = ปุ่มและลิงก์หายทันที (แชตที่ผูกไว้แล้วยังตอบปุ่มต่อได้)
**เทสต์:** `line_plan_smoke.py` — flag/ตั้งค่าไม่ครบ, ลิงก์ไม่มี token, รหัสซ้ำ/ข้ามบัญชี/หมดอายุ/เดา, ปุ่มตอบเร็ว, ความยินยอม, ขอเบอร์, พักบอท + CSRF, หยุดติดต่อ, คำขอเดิมจากฟอร์ม, ลีดที่มี LINE คนอื่น, webhook จริงพร้อมลายเซ็นและกันซ้ำ
**ก่อนเปิด flag จริง (เจ้าของ):** เปิดหน้าตั้งค่า LINE แล้วกดบันทึกหนึ่งครั้ง ให้ระบบอ่าน LINE ID ของ OA และเช็กว่าตรงกับ OA ที่ส่งรายงานอยู่ · webhook และ Auto-reply ใช้ของเดิม (OA นี้ส่งรายงานผ่านระบบอยู่แล้ว) · **ทดสอบลิงก์กับ OA จริง** ทั้งมือถือ (เป็นเพื่อนแล้ว/ยังไม่เป็น) และคอมพิวเตอร์ (ควรขึ้น QR) · ตกลงว่าใครตอบแชต · ข้อความแจ้งการใช้ข้อมูล (`line_plan.NOTICE`) ต้องให้คนตรวจกฎหมายพร้อมข้อความฟอร์ม
**ข้อจำกัด:** ยังไม่มีหน้านโยบายความเป็นส่วนตัวให้ลิงก์ · ไม่ดึงชื่อโปรไฟล์ LINE (ชื่อในคำขอ = "ลูกค้าจาก LINE" ถ้าลีดยังไม่มีชื่อ) · พักบอทเป็นรายห้อง 24 ชม. ไม่ได้ผูกกับโหมดแชตของ LINE OA Manager · `/callback` ยังไม่มีปุ่ม LINE (ไม่มีรายงานให้ผูก) · ยังไม่มีปฏิทินนัด (06A ส่วนที่เหลือ)

## stage 05-core — รายงาน 4 ช่อง
- `app/report_view.py` (ใหม่) อ่านของเดิมอย่างเดียว ไม่เขียน DB: `audit_json` + `snapshot_json` + `deep_json` + `deep_ai_json` → 4 ช่องตาม METRIC_DICTIONARY: ความพร้อมของเว็บ / การปรากฏในผลค้นเว็บ / AI พูดถึงแบรนด์ / AI อ้างอิงเว็บของคุณ
- ทุกช่องมีสถานะ found / absent / partial / not_tested / unavailable · ไม่ได้ทดสอบหรือระบบไม่พร้อม = ไม่มีตัวเลข (ไม่ใช่ 0) · ตัวหาร = ส่วนที่ทดสอบสำเร็จ (คำค้นหรือคำถามที่ล้มไม่นับ และติดป้ายได้บางส่วน) · บอกวิธีวัดทุกช่อง
- "สิ่งที่ควรทำก่อน" 3 ข้อ จากปัญหาที่ตรวจเจอจริง (Error จากการไต่เว็บก่อน แล้วข้อที่ตกในหน้าแรก) พร้อมหน้าและหลักฐาน · ไม่เดาเวลาทำงานหรือความมั่นใจ
- มาตรวัดความครอบคลุม (ตรวจแล้ว X จาก 4 ส่วน) + ขอบเขต: ตรวจแล้ว / ยังไม่ได้ตรวจ (รวม Search Console และผลทางธุรกิจ)
- `mk/report.html` แสดงที่ `/audit/{token}` เมื่อ `report_v2` active และภาษาไทย · ตารางละเอียดเดิมทั้งหมดอยู่ที่ `?view=full` · ภาษาอื่น = หน้าเดิม · noindex + no-store
- ระหว่างรายงานเต็มยังทำอยู่: JS เช็กทุก 6 วินาที โหลดหน้าใหม่เมื่อเสร็จ **เว้นแต่ผู้ใช้เริ่มพิมพ์ในฟอร์มแล้ว** (ไม่ทำให้ข้อความที่พิมพ์หาย)
- **แก้ชื่อ SoV (มีผลทันที):** `rank.html` "SoV บน AI" → "การปรากฏในผลค้นเว็บ" · `brand.html` ×2 และ `brand_content.html` "โผล่ใน AI" → "ปรากฏในผลค้นเว็บ" (แปล 4 ภาษาใหม่) · `db.py` docstring · คำอธิบาย PWA manifest (`main.py`) เลิกอ้างว่า "โผล่ในคำตอบ AI" · ไม่ได้แก้ข้อความทักใน LINE (`pipeline.py`) ที่ถามว่า "เว็บคุณโผล่ใน AI ไหม" เพราะเป็นคำถามชวนตรวจ ไม่ใช่ผลวัด
- **ยังไม่ได้ทำ (05-full):** เทียบคู่แข่งแบบเต็ม, ตัวอย่างข้อความที่ปรับแล้ว, ประวัติเวอร์ชันรายงาน, ปุ่มดูหลักฐานรายข้อ, ข้อมูลตาม METRIC_DICTIONARY §3 (protocol_id ฯลฯ ยังไม่มีในข้อมูลเดิม), ค่า `or 0` ใน `report.py` / `geo_worker.py` (รายงานลูกค้าที่ล็อกอิน) ยังไม่ได้แก้

### ผลข้างเคียงที่ตั้งใจ
- ลีดซ้ำโดเมนเพิ่มขึ้น (คนละคนตรวจโดเมนเดียวกัน = คนละลีด) → ทีมขายอาจเห็นโดเมนเดียวกันหลายแถว · รวมลีดเป็นงานของ stage 09
- คนที่ตรวจโดเมนเดียวกันจากคนละ IP จะทำให้ระบบไต่เว็บซ้ำ (จำกัดด้วย quota 5/IP/วัน เดิม)
- LINE event ถูกจองก่อนประมวลผล → ถ้าประมวลผลล้มกลางทาง LINE ส่งซ้ำจะไม่ถูกทำอีก (เลือกไม่ตอบซ้ำมากกว่าตอบสองครั้ง)

### ข้อจำกัดที่ยังเหลือ
- DNS rebinding: ตรวจตอน resolve แล้ว httpx resolve อีกรอบตอนต่อจริง
- ชื่อโฮสต์ที่ resolve ไม่ได้ตอนตรวจ ถูกปล่อยผ่าน
- `_client_ip` เชื่อ `X-Forwarded-For` ตัวแรกที่ client ส่งมา → ผู้ไม่หวังดีที่รู้ IP ของเหยื่อปลอม IP ได้ (ต้องให้ nginx เขียนทับ header นี้)
- `wp_client.py` (เชื่อม WordPress ของลูกค้าที่ล็อกอินแล้ว) ยังไม่ผ่านตัวกัน
- ตาราง `line_events_seen` ไม่มีการลบของเก่า (เพิ่มใน stage 10)
