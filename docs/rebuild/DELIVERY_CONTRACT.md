# ส่งมอบตามขอบเขต + พื้นที่งานลูกค้า (stage 15)

flag: `delivery_v2` (ปิดเป็นค่าเริ่มต้น · ปิด = แบบเดิมทุกอย่าง) · โค้ด: `app/delivery.py` · เทสต์: `delivery_smoke.py`
ตาราง: `delivery_workspaces`, `delivery_scopes`, `delivery_items` (เพิ่มอย่างเดียว)

## 1. ข้อเสนอ / สิทธิ์ / การใช้ แยกกัน

| เรื่อง | มาจาก | กฎ |
|---|---|---|
| ข้อเสนอใหม่ | setting `offer_drafts` (JSON) | สถานะร่างเสมอ · ไม่มีราคา = "ยังไม่ตั้งราคา" ระบบไม่เติมให้ · ไม่ย้ายลูกค้าเดิม |
| สิทธิ์ | `billing.PLANS` ของแพ็กเกจเดิม | อ่านอย่างเดียว · `auto_publish` ในแพ็กเกจ = ทำได้ทางเทคนิค ไม่ใช่การอนุญาตเผยแพร่ |
| การใช้ | `billing.usage` | แสดงคู่กับสิทธิ์ |

## 2. ขอบเขต (มีเวอร์ชัน)

ตอนเปิดพื้นที่งาน ระบบร่างขอบเขตเวอร์ชัน 1 ให้อัตโนมัติ ขอบเขตระบุ:
- สิ่งที่ส่งมอบ และสิ่งที่ไม่รวม
- ข้อมูลที่ลูกค้าต้องให้ และใครทำแต่ละส่วน
- รอบแก้ งานที่ต้องเสร็จก่อน เกณฑ์รับงาน และสมมติฐานเรื่องเวลา

ทีมกด "ลูกค้ายอมรับเวอร์ชันนี้" แล้วเวอร์ชันที่เคยยอมรับก่อนหน้าจะกลายเป็น "แทนแล้ว" งานแต่ละชิ้นบันทึกว่าอิงขอบเขตเวอร์ชันไหน

## 3. ลำดับ (ประตูแต่ละขั้น)

ยืนยันยอด → เปิดพื้นที่งาน → **ข้อมูลธุรกิจที่ลูกค้ายืนยัน + ผู้อนุมัติ** → **สิทธิ์เข้าถึง** → **วัดผลตั้งต้น** → **แผนที่อนุมัติ** → ลงมือ

| สถานะ | เมื่อไร |
|---|---|
| `awaiting_customer` รอข้อมูลจากคุณ | ยังไม่ยืนยันข้อมูลธุรกิจ/ผู้อนุมัติ หรือข้อมูลถูกแก้หลังยืนยัน |
| `awaiting_access` รอสิทธิ์เข้าถึง | ยังตรวจสิทธิ์ไม่ผ่าน (ตัวเชื่อม /geo · WordPress · หรือระบุผู้ติดต่อทีมเว็บเดิม) |
| `ready` พร้อมวางแผน | ยังไม่มีผลวัดตั้งต้น หรือแผนยังไม่ได้อนุมัติ |
| `in_progress` / `review` / `delivered` / `accepted` | คำนวณจากงานแต่ละชิ้น · ส่งบางส่วน = ยังเป็น `in_progress` |
| `blocked` / `cancelled` | ทีมตั้งพร้อมเหตุผล |

- การจ่ายเงินไม่ได้แปลว่าพร้อม และไม่ได้แปลว่าอนุญาตให้เผยแพร่
    - `publish_allowed` ต้องให้ลูกค้าติ๊กเอง
    - ถ้าเลือกให้ทีมเว็บเดิมดูแล ค่านี้จะเป็น 0 เสมอ
- **ไม่มีการวิ่งเองโดยไม่ตั้งใจ** เมื่อเปิด flag:
    - ยืนยันยอดแล้ว ระบบเปิดพื้นที่งานแต่ไม่สั่ง Autopilot
    - วันที่ 7 ระบบไม่สั่ง Autopilot อีกรอบ
    - `run_autopilot` (ทั้งรอบรายสัปดาห์และการกดเอง) จะข้ามจนกว่าพื้นที่งานถึงขั้นลงมือ และเมื่อวิ่งได้แล้ว จะบังคับโหมด "ร่าง" ถ้ายังไม่ได้รับอนุญาตให้เผยแพร่
- **ลูกค้าเดิม** ที่ไม่มีพื้นที่งาน ใช้สัญญาและ Autopilot เดิมทุกอย่าง

## 4. วางแผน (ใช้ผลตรวจเดิม)

ประเภทงาน: investigate · fix_technical · confirm_facts · update_existing · consolidate · add_evidence · create_page · create_article · internal_links · wait · no_action

| ผลตรวจ | งานที่ได้ |
|---|---|
| ปัญหาระดับ Error/Warning (ไม่เอา Notice) | fix_technical ไม่เกิน 5 งาน · หน้าซ้ำรวมเป็น consolidate งานเดียว |
| AI ยังไม่ได้ทดสอบ | investigate (ไม่ถือว่าเป็น 0) |
| AI ไม่เอ่ยถึง (กี่คำถามก็ตาม) | **งานเดียว**: update_existing ถ้ามีหน้าที่ตรงบริการหลัก ไม่งั้น create_page · ตามด้วย internal_links ที่ต้องรองานนั้น · **ไม่เขียนบทความต่อคำถาม** |
| AI เอ่ยถึงแล้ว | wait |
| ไม่มีอะไรคุ้มทำ | no_action |

- ทุกงานระบุหลักฐาน ใครทำ (ทีมเรา / ทีมเว็บของลูกค้า / ลูกค้า) และเกณฑ์รับงาน
- ถ้าลูกค้าใช้ทีมเว็บเดิม งานเทคนิคทั้งหมดเป็นของทีมเว็บลูกค้า
- ร่างแผนใหม่จะแทนร่างเดิมที่ยังไม่เริ่ม และต้องอนุมัติใหม่ทุกครั้ง

## 5. กฎของงานแต่ละชิ้น

- เริ่มงานได้เมื่อแผนได้รับอนุมัติแล้วเท่านั้น
- งานที่มีงานต้องรอ (`depends_on`) จะเริ่มไม่ได้จนกว่างานนั้นส่งมอบแล้ว ระหว่างนั้นสถานะเป็น "ติดปัญหา" และระบุว่ารองานไหน
- **ข้อมูลธุรกิจเปลี่ยน** (ลูกค้าบันทึกเวอร์ชันใหม่):
    - งานที่ยังไม่ส่งมอบกลายเป็น "ข้อมูลเปลี่ยน ต้องร่างใหม่" และเริ่มไม่ได้
    - การอนุมัติแผนถูกยกเลิก และพื้นที่งานกลับไปรอให้ลูกค้ายืนยันข้อมูลใหม่
    - งานที่ส่งมอบแล้วไม่ย้อนกลับ
- ระบบไม่ถือว่าลูกค้ารับงานเองอัตโนมัติ ลูกค้าต้องกด หรือทีมบันทึกให้

## 6. หน้าจอ

- **ลูกค้า `/app/delivery`:**
    - สถานะและขั้นถัดไป
    - รอคุณอยู่: ข้อมูล สิทธิ์ อนุมัติแผน ตรวจงาน และงานของทีมเว็บลูกค้า
    - ฟอร์มข้อมูลธุรกิจ + ผู้อนุมัติ และฟอร์มสิทธิ์เข้าถึง
    - ผลวัดตั้งต้นแบบแยกสถานะ: ยังไม่ได้ทดสอบจะไม่แสดงตัวเลข
    - แผนพร้อมหลักฐาน ปุ่มอนุมัติแผน และปุ่มรับงาน
    - ขอบเขตงาน และสิทธิ์/การใช้ตามแพ็กเกจ
    - เห็นเฉพาะพื้นที่งานของบัญชีตัวเอง
- **หน้าหลัก `/app`:** แถบสถานะและขั้นถัดไป เครื่องมือเดิม (มอนิเตอร์ คอนเทนต์ สุขภาพเว็บ GSC AI) ยังอยู่ครบ
- **แอดมิน `/admin/delivery`:**
    - สิทธิ์อยู่หมวด "ลูกค้าและผลงาน"
    - บันทึกผลวัดตั้งต้น ร่างแผน และยอมรับขอบเขต
    - เปลี่ยนสถานะงาน: เริ่ม / ส่งตรวจ / ส่งมอบ / ติดปัญหา / ยกเลิก
    - ตั้งพื้นที่งานเป็นติดปัญหา หรือยกเลิก
    - ร่างข้อเสนอ
- **พันธมิตร `/partner/<token>`:** เห็นแค่โดเมน สถานะ และขั้นถัดไปของลูกค้าที่ตัวเองแนะนำ ไม่เห็นข้อมูลธุรกิจ สิทธิ์เข้าถึง หรือผลวัด

## ยังไม่ครอบคลุม

- ยังไม่มีอีเมลหรือ LINE แจ้งลูกค้าเมื่อสถานะเปลี่ยน (ไม่ส่งอะไรจริงในขั้นนี้)
- add_evidence และ create_article ยังไม่มีกฎสร้างอัตโนมัติ (ทีมเพิ่มได้ในขั้นถัดไป)
- เมื่อเปิด flag ลูกค้าใหม่จะไม่ได้รับอีเมล kickoff "แผน 30 วัน" แบบเดิม เพราะอีเมลนั้นสัญญาว่า Autopilot เริ่มทันที ต้องเขียนข้อความใหม่ให้ตรงกับขั้นตอนนี้ก่อน
- ยังไม่ได้ทดสอบ Postgres
