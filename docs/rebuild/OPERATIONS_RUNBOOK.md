## 3. งานตามเวลา (ใครเป็นเจ้าของ)

- **เลือกตัวตั้งเวลาให้มีเจ้าของเดียว** จะใช้ cron (`run_monitors.py`) หรือ GEO_AUTORUN=1 ในแอปก็ได้ แต่ห้ามใช้ทั้งสองแบบกับงานรอบแบรนด์เดียวกัน
- ถ้าใช้ GEO_AUTORUN กับ uvicorn หลาย worker ให้เปิด `scheduler_lease`
- คิวงาน (`--jobs`) รันซ้อนกันได้ เพราะการรับงาน (claim) เป็น CAS
- รูปแบบ cron (เวลาไทย ต้องตรวจกับ crontab จริงของเครื่องก่อน):

```
*/5 * * * *  cd <app> && .venv/bin/python run_monitors.py --jobs        # คิวงาน (เมื่อเปิด durable_jobs)
0 7 * * *    cd <app> && .venv/bin/python run_monitors.py --plan        # CEO แจกงาน
30 10 * * *  cd <app> && .venv/bin/python run_monitors.py --success     # ดูแลลูกค้า
0 9 * * 1    cd <app> && .venv/bin/python run_monitors.py --autopilot   # Autopilot รายสัปดาห์
```

## 4. ระบายงานก่อน deploy / ก่อนปิด flag (draining)

1. กด "หยุดคิวทั้งหมด (kill switch)" ที่ `/admin/jobs` → งานใหม่จะไม่ถูกรับ ส่วนงานที่กำลังทำจะทำจนจบหรือหมด lease (15 นาที)
2. รอจนสถานะ "กำลังทำ" เป็น 0 (ดูที่ `/admin/jobs?status=running`)
3. ถ้าจำเป็น ให้ "หยุดเอเจนต์ทั้งหมด" ที่ `/admin/tasks` ด้วย
4. deploy หรือปิด flag
5. เปิดคิวกลับ งานที่ค้างจะตรวจสถานะล่าสุดก่อนทำเสมอ: นัดที่เปลี่ยน ลูกค้าที่ขอหยุด และเนื้อหาที่ถูกแก้ จะถูกยกเลิก ไม่ส่งของเก่า

## 5. เฝ้าดู (monitoring)

| ดูที่ | ผิดปกติเมื่อ |
|---|---|
| `/admin/jobs` | งาน "ล้มถาวร" เพิ่มขึ้น · "กำลังทำ" ค้างเกิน 15 นาที · งบวันนี้เต็มตั้งแต่เช้า |
| `/admin/tasks` (flag agent_policy) | "ไม่อนุญาต/วนซ้ำ" เพิ่มขึ้น · มีธง "อีเมลพยายามสั่ง AI" |

| `/brands/<id>/publishing` | คำขอ "ไม่แน่ใจผล" — ต้องกด "ตรวจปลายทาง" ห้ามกดเผยแพร่ซ้ำ |

## 6. กู้คืน (recovery)

| เหตุ | ทำอะไร |
|---|---|
| งานในคิวค้าง "กำลังทำ" | ไม่ต้องทำอะไร เพราะ `recover()` คืนงานเมื่อ lease หมด ถ้าด่วน ให้ยกเลิกแล้วสั่งใหม่ที่ `/admin/jobs` |
| ส่งข้อความผิด / สงสัยว่าส่งซ้ำ | กด kill switch แล้วดู outbox ที่ `/admin/jobs` (ช่วงนี้ยังเป็นโหมดทดสอบ ไม่ส่งจริง) |
| เผยแพร่ผิดชิ้น | `/brands/<id>/publishing` → "คืนเวอร์ชันก่อนหน้า" (กระทบเฉพาะชิ้นนั้น) ถ้าปลายทางคืนไม่ได้ ระบบจะบอก ให้แก้ที่ปลายทางเอง |
| flag ใหม่ทำงานผิด | ปิด flag นั้น ข้อมูลยังอยู่ ระบบกลับไปใช้ทางเดิม (ดู ROLLBACK_RUNBOOK.md) |
| ฐานข้อมูลเสีย | กู้จากไฟล์สำรองตาม MIGRATION_RUNBOOK.md ข้อ 5 |

## 8. ตั้งค่าที่เจ้าของ/ผู้ดูแลต้องใส่เอง (ไม่มีค่าในเอกสารนี้)

- `SESSION_SECRET` ต้องตั้งเป็นค่าสุ่มยาว ถ้าไม่ตั้ง ระบบจะใช้ "dev-secret-change-me" ซึ่งห้ามใช้บน production
- `PUBLIC_BASE_URL` ใช้ทั้ง canonical และ origin_check
- `budget_ai_usd_daily`, `fx_usd_thb`, `agent_capacity_daily`, `agent_priority` ตั้งเป็น setting ในแอป
- ข้อมูลรับรองของ LINE OA, Stripe, SMTP และ WordPress ใส่ที่หน้าตั้งค่าโดยเจ้าของ ห้ามส่งผ่านแชต
