## 1. ผลตรวจที่ทำจริง

### 1.1 เทสต์อัตโนมัติ
- ชุดเทสต์ทั้งหมด `*_smoke.py` (ข้าม `pg_smoke.py` ซึ่งต้องมี Postgres): **72/72 ผ่าน** (2026-11-15)
- `qa_release_smoke.py` (ใหม่ stage 08A) ตรวจ:
  - หน้าสาธารณะ 5 หน้า (`/`, `/how-it-works`, `/services`, `/services/foundation-sprint`, `/solutions/industrial-property`) เมื่อเปิด flag: title และ description ไม่ซ้ำกัน (description 50–200 ตัวอักษร) · canonical ชี้ตัวเองบนโดเมนเดียวกับ sitemap · h1 หน้าละ 1 · `lang="th"` · ไม่มี noindex
  - ทุกช่องกรอกมีป้าย (label for / ครอบด้วย label / aria-label) · ทุกฟอร์มส่งได้โดยไม่ต้องมี JS (มี action + method) ยกเว้นแชตเสริมที่ต้องใช้ JS อยู่แล้ว · รูปทุกรูปมี alt · ไม่มีลิงก์ `javascript:`
  - ลิงก์ภายในทุกลิงก์จากหน้าเหล่านี้ไม่เสีย (ไม่มี 4xx/5xx)
  - ข้อมูลโครงสร้าง: หน้าแรกมี Organization (ชื่อ ที่อยู่เว็บ คำอธิบาย) + FAQPage ที่คำถามและคำตอบตรงกับที่แสดงบนหน้า · ไม่มีคะแนนรีวิวหรือรีวิว
  - sitemap มีเฉพาะหน้าสาธารณะ ทุก URL เปิดได้ (200) และไม่ noindex · robots.txt กัน `/audit/ /q/ /bill/ /doc/ /admin /u/ /partner/` และชี้ sitemap
  - หน้าลิงก์ลับ/หลังล็อกอิน รวม PDF: `X-Robots-Tag: noindex, nofollow` · `Cache-Control` เป็น private/no-store (ไม่มี public) · `Referrer-Policy: no-referrer`
  - service worker: แคชเฉพาะ `/static/` · หน้าเว็บดึงจากเซิร์ฟเวอร์ทุกครั้งและไม่เก็บลงแคช · ไม่แตะคำขอที่ไม่ใช่ GET · ตัว `sw.js` เป็น `no-cache` และมีเลขเวอร์ชันแคช (`geo-v3`)
  - เส้นทางลูกค้า: รายงาน → ยืนยันข้อมูลธุรกิจ → เห็นหลักฐานและตัวอย่างร่าง → ขอแผน → ขั้นต่อไปเปลี่ยนเป็นรอนัดคุย → ทีมส่งใบเสนอราคา → ขั้นต่อไปเป็นดูใบเสนอราคา → แอดมินเห็น Sales Brief ที่มีข้อมูลที่ลูกค้ายืนยัน
  - flag ปิด: หน้าแรก `/audit` `/partners` `/login` robots sitemap ทำงาน · หน้าใหม่ 404 · รายงานเป็นหน้าเดิม
- เส้นทางอื่นที่มีเทสต์อยู่แล้ว (ไม่ได้เขียนใหม่): ตรวจเว็บแบบเร็ว partial/สำเร็จ (`snapshot_smoke.py`) · ขอแผน (`report_plan_smoke.py`) · ยืนยันข้อมูลธุรกิจ (`business_context_smoke.py`) · รายงานเต็ม 7 กรณี (`report_full_smoke.py`) · LINE (`line_plan_smoke.py`) · ใบเสนอราคา (`quote_i18n_smoke.py`) · ยกเลิกรับอีเมลหน้า `/u/` (`phase2_smoke.py`) · พันธมิตร (`partners_smoke.py`) · ลูกค้าที่ล็อกอิน (`customers_smoke.py`)

"ไม่ล้น" = ความกว้างเนื้อหาเท่าจอ ไม่มีองค์ประกอบเกินขอบขวา (ตารางในรายงานเลื่อนในกรอบของตัวเองได้ตามตั้งใจ) · รูปที่ไม่มี alt: 0 ทุกหน้า
- คีย์บอร์ด (หน้าแรก 360px): Tab แรก = ลิงก์ "ข้ามไปเนื้อหา" · ไปถึงช่องกรอกเว็บไซต์ใน 9 ครั้ง · กรอบโฟกัสเห็นชัด (เส้นสีส้ม 3px)
- ลดการเคลื่อนไหว: มี `prefers-reduced-motion` ปิด transition/animation ทั้งหมด (ตรวจจาก CSS ไม่ได้ทดสอบกับการตั้งค่าเครื่องจริง)
- ไม่มี JS: ฟอร์มตรวจเว็บ ยืนยันข้อมูลธุรกิจ และขอแผน เป็น POST ธรรมดา · หน้ารอผลโหลดใหม่เองด้วย meta refresh · ส่วนพับใช้ `<details>`
- สื่อ: ยังไม่มีวิดีโอ/รูปจริงบนหน้าใหม่ · macro สื่อใช้ `loading="lazy"` และวิดีโอ `preload="none"` ไม่เล่นเอง

### 1.3 เครื่องมือที่ไม่ได้รัน
- **ไม่ได้รัน Lighthouse / axe / ตัวตรวจ SEO ภายนอก** เพราะเครื่องนี้ไม่มี Node/npx · ไม่มีคะแนนประสิทธิภาพหรือ accessibility จากเครื่องมือ (ไม่เดาคะแนนแทน) → ควรรันบน staging
- ไม่ได้ทดสอบกับ screen reader จริง และไม่ได้ทดสอบบนมือถือจริง (ใช้การจำลองขนาดจอ)
- ไม่ได้ทดสอบ Rich Results Test ของ Google (ต้องเป็น URL สาธารณะ)

## 2. สิ่งที่แก้ใน stage 08A
1. **หน้าลิงก์ลับไม่มี header กัน index/แคช** โดยเฉพาะ PDF ใบเสนอราคา บิล เอกสาร (PDF ใส่ meta robots ไม่ได้) → เพิ่ม middleware `_private_headers` ใน `app/main.py` ใช้กับ `/audit/… /q/ /bill/ /doc/ /u/ /partner/ /contract /app /admin /account /brands /preview /chat/ /upgrade /notifications /pay` (**มีผลทันที ไม่ผ่าน flag** · ไม่เปลี่ยนเนื้อหาหน้า เปลี่ยนแค่ header)

3. **ไม่มีข้อมูลโครงสร้างบนหน้าใหม่** → Organization + FAQPage บนหน้าแรก จากข้อความที่แสดงเท่านั้น (หลัง flag)

## 4. Flag · การเปลี่ยนฐานข้อมูล · ย้อนกลับ · แคช

### Flag (ค่าเริ่มต้นปิดทั้งหมด · เปิดได้ที่ setting `flag_<name>` หรือ env `GEO_FLAG_<NAME>`)
| flag | เปิดแล้วได้อะไร | ต้องเปิดคู่ |
|---|---|---|
| `marketing_v2` | หน้าแรกใหม่ (ไทย) + หน้า stage 03 + sitemap รวมหน้าใหม่ | — |
| `snapshot_v2` | ตรวจเว็บแบบเร็ว ≤5 หน้า + หน้าสถานะจริง | — |
| `report_v2` | รายงาน 4 ช่อง + รายงานเต็ม (หลักฐาน ประวัติ เทียบคู่แข่ง) | แนะนำคู่ `snapshot_v2` |
| `plan_request_v2` | ฟอร์มขอแผน + Sales Brief | `report_v2` |
| `context_v2` | ยืนยันข้อมูลธุรกิจ + ตัวอย่างร่าง | `report_v2` |

ลำดับเปิดบน staging ที่แนะนำ: `marketing_v2` → `snapshot_v2` + `report_v2` → `context_v2` → `plan_request_v2` (หลังตรวจกฎหมาย) → `line_appointments` (หลังทดสอบ OA)
แอดมินดูก่อนเปิดจริงได้ด้วยโหมด preview (คุกกี้ `jr_preview`) โดยไม่กระทบผู้เยี่ยมชม

### การเปลี่ยนฐานข้อมูล (เพิ่มอย่างเดียว · สร้างเองตอนแอปเริ่ม · ไม่แก้/ลบข้อมูลเดิม)
- ตารางใหม่: `plan_requests`, `business_contexts`, `report_versions`, `line_plan_codes`, `line_plan_sessions`
- คอลัมน์ใหม่ใน `leads`: `snapshot_json`
- ข้อมูลเดิม (`audit_json`, `deep_json`, `deep_ai_json`) อ่านอย่างเดียว · การตรวจรอบใหม่เพิ่มฟิลด์ `protocol` และ `excerpt` ใน JSON (ของเก่าไม่มีก็แสดงได้)
- ยังไม่มีตาราง `schema_migrations` (เสนอใน DATA_CONTRACTS) → ก่อน production ควรสำรองฐานข้อมูลก่อนเปิดแอปเวอร์ชันใหม่

### ย้อนกลับ
- **ปัญหาที่หน้าเว็บ:** ปิด flag ที่เกี่ยวข้อง → กลับเป็นหน้าเดิมทันที ไม่ต้อง deploy ใหม่ ข้อมูลที่ลูกค้ากรอกไว้ยังอยู่
- **ปัญหาที่โค้ด:** deploy commit ก่อนหน้า · ตารางใหม่ค้างอยู่ได้ (โค้ดเก่าไม่อ่าน) ไม่ต้องลบ
- middleware header ส่วนตัว (ข้อ 2.1) ไม่มี flag → ถ้าต้องย้อนต้อง deploy commit ก่อนหน้า (ไม่น่าต้องย้อน: เปลี่ยนแค่ header)

### แคช
- หน้า HTML ทั้งหมด `no-store` อยู่แล้ว (middleware เดิม) · หน้าลิงก์ลับ `private, no-store` + `no-referrer`
- `robots.txt` แคช 1 วัน · `sitemap.xml` 1 ชม. → หลังเปิด `marketing_v2` sitemap ใหม่อาจมาช้าสูงสุด 1 ชม.
- service worker ไม่แคชหน้าเว็บ → เปลี่ยนหน้าแล้วผู้ใช้เห็นทันที · ถ้าเปลี่ยนไฟล์ใน `/static/` ที่ใช้ชื่อเดิม ต้องขยับเลข `CACHE` ใน `_SW_JS` (ตอนนี้ `geo-v3`) ไม่งั้นผู้ใช้ที่ติดตั้ง PWA อาจเห็นไฟล์เก่า · stage 01–08A ไม่ได้เปลี่ยนไฟล์ใน `/static/`
- ถ้ามี CDN/proxy หน้า server ต้องเคารพ `Cache-Control` (ไม่ override เป็น public) — ผู้ดูแล server ตรวจ
